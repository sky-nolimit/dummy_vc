- 目标环境：Ubuntu 22.04 + ROS 2 Humble
- 硬件：Dummy 机械臂（ODrive/fibre 接口）+ 深度相机（待到位）
- 首期验收：可复现的桌面抓取 Demo（识别 → 规划 → 抓取 → 放置）

## 1. 资料盘点与定位

| 项目 | 定位 | 结论 |
|---|---|---|
| `dummy2_urdf` | 机械臂描述（URDF/Xacro + STL） | **采用**，作为唯一模型来源 |

### 1.1 从 dummy2_urdf 拿到的关键信息

关节链（base_link 起）：

             └ dummy2_joint4 revolute axis (+y) ±3.1416   原点 (-0.013162,0.001543,0.062467)
               └ link5_v3_1
                 └ dummy2_joint5 revolute axis (+x) ±1.7453 原点 (0.0228,0.11,0)
                   └ link6_v3_1
                     └ dummy2_joint6 revolute axis (-y) ±3.1416 原点 (-0.021,0.1185,0)
                       └ link7_v1_1

                             └ dummy2_finger_joint2 prismatic axis(-x) 0~0.023

要点：
1. **6 个旋转关节 + 1 个固定手爪 + 2 个平移手指**。手指行程各 23 mm，即最大开口约 46 mm，两指同向对开（joint1 沿 +x，joint2 沿 -x）。
2. **URDF 里没有相机 frame**，也没有 TCP/tool0 frame，需要我们自己补。
3. **URDF 里没有 `world` link**，MoveIt 需要一个虚拟关节或基座固定 frame。

### 1.2.1 实机接口树（已探测，2025 实测）

```
serial_number = 327934543234
get_temperature() / get_voltage()

robot:
  calibrate_home_offset()      homing()      resting()
  joint_1 .. joint_6:  angle(float)  update_angle()
      set_position(pos)             set_velocity(vel)         set_current(cur)
      set_position_with_time(pos, time)                       ← 轨迹执行关键
      set_velocity_limit / set_current_limit / set_acceleration
      set_enable(bool) / set_enable_on_boot / set_enable_temperature
      apply_home_offset() / do_calibration() / erase_configs() / reboot()
      set_node_id(id)   set_dce_kp/kv/ki/kd   set_enable_stall_protect
  joint_all:  angle(float) + 全套同名方法     ← 6 关节联动端点
  hand:                                          ← ★ 夹爪就在这里
      set_angle(angle: float)
      set_enable(enable: bool)
      set_current_limit(current: float)
  reboot() / set_enable(bool) / set_rgb_enable / set_rgb_mode
  move_j(j1..j6)   move_l(x,y,z,a,b,c)
  set_joint_speed(speed)   set_joint_acc(acc)   set_command_mode(mode)
  tuning: set_tuning_freq_amp(freq, amp) / set_tuning_flag(flag)
```

**这份接口树解决了阻塞 6，并且顺带解决/暴露了另外几件事：**

| 发现 | 意义 |
|---|---|
| `robot.hand.set_angle(angle)` | **夹爪有接口**，不需要额外硬件。抓取闭环可行 |
| `hand.set_current_limit(current)` | 可做**夹持力控制**，是"夹住不掉又不夹碎"的唯一手段 |
| `hand.set_enable(bool)` | 夹爪需要单独使能，别只使能 6 个关节 |
| `joint_N.set_position_with_time(pos, time)` | 可**按时间预算下发轨迹点**，比 `move_j` 更适合执行 MoveIt 轨迹 |
| `robot.set_joint_speed` / `set_joint_acc` | 全局速度/加速度设置，是限速的正确入口（比在 ROS 侧降采样更安全） |
| `robot.homing()` / `resting()` / `calibrate_home_offset()` | 存在正式回零流程，应作为开机初始化，而不是像现在直接 `move_j` 回 7 字位 |
| `joint_N.update_angle()` | `angle` 是缓存值，高频轮询前可能需要先 `update_angle()` |
| `set_command_mode(mode)` | 模式切换存在，**误用会导致电机不受位置控制**，初期不要碰 |
| `set_enable_stall_protect(bool)` | 堵转保护，夹爪/关节撞限位时的安全网 |
| **没有 `move_l` 的位姿回读接口** | 印证了 §2 阻塞判断：`move_l` 只进不出，不要依赖它做闭环 |

### 1.3 dummy_moveit_ws 里值得借鉴的部分（只抄思路，不抄代码）

1. `dummy_arm_controller.py` 的 `rad_fix()` 揭示了硬件角度与 ROS 标准角度的映射：

3. `dummy-ros2.srdf` 的 group state、MoveIt 配置目录结构、`demo_with_usb.launch.py` 的分层 launch 写法值得参考。

## 2. 必须先修掉的 6 个阻塞问题

修完这 6 项，`dummy2_urdf` 与 `dummy_ros2_driver` 才第一次能在 RViz 里同步显示真实姿态。**阻塞 6 已因接口探测而解决**，其余 5 项现状如下。

### 阻塞 1 —— 关节名三方不一致（最致命）

| 来源 | 关节名 |
|---|---|
| `dummy2_urdf` | `dummy2_joint1` … `dummy2_joint6` |
| driver 发的 `/joint_states` | `joint_1` … `joint_6` |
| `dummy_moveit_ws` 配置 | `joint1` … `joint6` |

`robot_state_publisher` 拿到的 `JointState.name` 在 URDF 里找不到 → 静默忽略 → TF 树里 `base_link` 到末端全是死的，RViz 里机械臂不动，MoveIt 也算不出正确末端位姿。

**决策**：统一到 URDF 的 `dummy2_jointN`，在 driver 里改 `self.joint_names`，MoveIt 配置全部按 `dummy2_jointN` 生成。理由：URDF 是模型真相来源，改名字比改 STL 和几十处 xacro 便宜。

### 阻塞 2 —— 轨迹只执行第一个点

`dummy_controller.py` 的 `joints_callback()`：
```python
positions = msg.points[0].positions   # 只取 points[0]
```
MoveIt 规划出来的是几十个 waypoint 的完整轨迹，这样写等于**只跳到轨迹终点**，直接抛弃了整条插值路径。轻则动作难看，重则瞬时大角度跳变损伤减速器。

**决策**：按 `points[i].time_from_start` 节拍依次下发，**优先用 `joint_N.set_position_with_time(pos, time)` 让固件自己按时间走**，比在 ROS 侧 `time.sleep` 更精确、不吃 Python 的时序抖动。同时在 `move_group` 侧把 `max_velocity_scaling_factor` 压到 0.1~0.2 起步。上位机侧的节拍循环仍要保留作为兜底（固件若不支持则退回 sleep 方案）。

### 阻塞 3 —— 单位不匹配

`joints_callback` 里做了 `np.degrees(positions)` 再调 `move_j`，这与 `home_joints = [0,0,90,0,0,0]`（度）一致，说明 `move_j` 收度。而 `check_joints_place()` 却拿度和弧度直接比。需统一：**ROS 侧一律弧度，只在调用 `move_j` 的最后一步转度**。

### 阻塞 4 —— lifecycle 需要手动触发

代码里订阅器只在 `on_activate` 创建。也就是说启动后必须手工执行：
```
ros2 lifecycle set /dummy_controller configure
ros2 lifecycle set /dummy_controller activate
```
否则话题订阅根本不存在，发指令没反应，而且不会有任何报错。**决策**：新增一个 launch 文件用 `emit_event` 自动跑完 configure → activate，避免每次手动敲。

### 阻塞 5 —— TF 树是断的

driver 广播 `joint6 → tool0` 和 `joint6 → camera_frame`，但 URDF 里根本没有叫 `joint6` 的 frame（只有 `dummy2_joint6`，而 URDF 里 frame 名对应的是 **link** 名，`joint6` 既不是 link 也不是 joint 的 TF frame）。同时相机节点用的 frame_id 是 `fingerprint_camera`，跟 `camera_frame` 又对不上。

**决策**：删掉 driver 里所有手写 TF 广播，全部改为在 URDF/xacro 里静态定义（`tool0`、`gripper_tcp`、`camera_link`、`camera_color_optical_frame`），交给 `robot_state_publisher` 统一算。

### 阻塞 6 —— 没有夹爪接口

driver 从头到尾没有任何夹爪调用，`ref_tool` 里也搜不到。而"抓取"必须有夹爪开合。

**决策（已定）**：接口树确认 `robot.hand` 就在同一个 fibre 设备上，**不需要额外硬件、不需要第二个节点**。在 driver 里新增：

| 接口 | 类型 | 含义 |
|---|---|---|
| `/dummy_gripper/command` | `std_msgs/Float64` | 归一化开口，0.0 = 全闭，1.0 = 全开 |
| `/dummy_gripper/command` | `control_msgs/GripperCommand`（动作） | MoveIt / 状态机用，带 `position` + `max_effort` |
| `/dummy_gripper/state` | `sensor_msgs/JointState` | 两个手指的等效 prismatic 位置，喂给 `robot_state_publisher` |

实现要点：
1. `hand.set_enable(True)` 必须单独调用，`robot.set_enable(True)` 不覆盖夹爪。
2. `max_effort` 映射到 `hand.set_current_limit()`，这是防夹碎的唯一手段。
3. 归一化开口 → `hand.set_angle()` 的角度换算需要**实测标定**（见 §4 阶段 0.5）。
4. 手指的 prismatic 位置（0 ~ 0.023 m）与 `hand.angle` 的映射关系待定，先按线性假设，实测后修正。

### 3.3 坐标系与 TCP 定义

在 xacro 里补齐（数值需按实物测量确认）：

```xml
<!-- 末端夹持中心：从 link7 沿 +y 方向偏移到两指中心 -->
<link name="tool0"/>
<joint name="tool0_joint" type="fixed">
  <parent link="link7_v1_1"/>
  <child  link="tool0"/>
  <origin xyz="0 0.052312 0" rpy="0 0 0"/>
</joint>

<!-- 抓取 TCP：两指中心、指尖前端（具体偏移量必须实测） -->
<link name="gripper_tcp"/>
<joint name="gripper_tcp_joint" type="fixed">
  <parent link="tool0"/>
  <child  link="gripper_tcp"/>
  <origin xyz="0 0.06 0" rpy="0 0 0"/>   <!-- 0.06 为占位，需实测 -->
</joint>
```

MoveIt 的规划链定义为 `base_link → gripper_tcp`（**不是 link6**，参考项目用 link6 是因为它没有夹爪）。

**相机（eye-in-hand 已确认）**：相机装在机械臂末端，所以相机 frame 挂在 `tool0` 下，需要**两级**：

```xml
<link name="camera_link"/>
<joint name="camera_link_joint" type="fixed">
  <parent link="tool0"/>
  <child  link="camera_link"/>
  <!-- 手眼标定结果写在这里：tool0 → camera_link -->
  <origin xyz="0 0.02 0.025" rpy="0 0 0"/>   <!-- 占位，标定后替换 -->
</joint>
```

RealSense 驱动自己会发布 `camera_link → camera_color_optical_frame`，接上去即可。注意 optical frame 的约定是 **z 朝前、x 朝右、y 朝下**，与 URDF 的 x 朝前惯例不同，`rpy` 得写成 `(-π/2, 0, -π/2)` 那种形式；写抓取变换时最容易在这里翻车，务必用 `tf2_echo` 验证 optical frame 的 z 轴确实指向物体。

**eye-in-hand 带来的一个必须处理的几何问题**：相机现在（`fingerprint_camera` 的布置）就夹在两指之间朝前看，标定/检测时它有视野，但**抓取过程的最后一段下降会让手指进入视野甚至遮住目标**。定量的盲区半径约为

```
r_blind ≈ (指间开口 / 2) / tan(水平FOV / 2)
```

对策（阶段 5 实现）：
1. **只在接近前做一次观测**，把目标点变换到 `base_link` 后**冻结**，下降段不再依赖视觉。
2. 冻结时把 `gripper_tcp` 的目标位姿换算好，抓取过程就是纯 MoveIt 关节运动 + TF 保证，与视觉脱钩。
3. 如果需要下降中持续修正（视觉伺服），必须把相机前移到手指尖**之前**，或改用侧装 —— 这是硬件改动，不建议首期做。

## 4. 分阶段实施计划

### 阶段 0：接口探测与实测标定（1 天）

0.1 已完成 —— 接口树见 §1.2.1。剩下的是**纯粹靠实测才能确定的量**，这些必须在上位机代码之前锁定：

| 步骤 | 动作 | 产出 | 备注 |
|---|---|---|---|
| 0.2 | `robot.homing()` / `resting()` / `calibrate_home_offset()` 各跑一次，观察动作 | **正式回零流程** | 替代现在直接 `move_j` 回 7 字位的做法 |
| 0.3 | 逐关节 `joint_N.set_position(±0.3)`，同时 `ros2 run tf2_ros tf2_echo` 看 RViz | **实测关节方向表 + 单位表** | 见下方"为什么不能跳" |
| 0.4 | `hand.set_enable(True)`，然后 `hand.set_angle()` 从 0 扫到上限 | **角度范围 + 0 点定义** | 确认 0 是全闭还是全开 |
| 0.5 | 夹爪夹住不同厚度物体，读 `hand.angle` 与两指实际间距 | **angle ↔ 开口宽度 映射表** | 喂给 URDF 的 prismatic joint，也用于判断能否夹住目标 |
| 0.6 | `hand.set_current_limit()` 从低到高扫，找"夹稳不滑"和"不夹碎"的区间 | **夹持力参数** | 用鸡蛋/纸杯做上限测试 |
| 0.7 | `joint_1.set_position_with_time(0.2, 1.0)` 等几种组合 | **确认 pos/time 的单位** | pos 是度还是弧度？time 是秒还是毫秒？ |
| 0.8 | 用尺子量 `link7` 末端到两指夹持中心的距离 | **`gripper_tcp` 的真实偏移量** | 写进 xacro，也决定 MoveIt 的 IK 精度 |

**为什么 0.3 不能跳**：URDF 里 j1 轴是 `-z`、j5 是 `-x`、j6 是 `-y`，符号是原作者建模时的选择；`move_j` 收度而 `angle` 回读是弧度，`dummy_moveit_ws` 的 `rad_fix()` 还额外有 `[0,0,+90°,0,0,0]` 的偏置和 `[1,1,1,1,-1,-1]` 的反向。这三层叠加起来，**任何一处猜错都会让整个运动学系统性镜像**，而症状（末端跑到桌子另一边）与"标定不准"极难区分。逐关节实测半小时，能省掉后面几天的排查。

**为什么 0.5 和 0.8 必须实测**：URDF 里手指行程标的是 0~0.023 m，但硬件接口给的是 `hand.angle`。两者之间没有公开的换算关系，只能量。这个映射直接决定 `gripper_tcp` 能不能对准物体中心，误差 5 mm 就足以让抓取从"抓住"变成"推倒"。

**验收**：产出一张表，含 6 个关节的方向符号、单位、零点偏置，以及夹爪角度范围、力上限、开口映射、TCP 偏移。这张表是后面所有阶段的输入。

### 阶段 4：视觉感知（2~3 天）

相机未到前，先用 driver 里现成的 USB 相机 + 内参把算法框架搭起来，**接口按深度相机的标准设计**，相机到位后只换数据源。注意 USB 相机节点现在的 `camera_frame_id` 是 `fingerprint_camera`，必须改成与 xacro 里 `camera_link` 一致。

```
/detected_objects  (vision_msgs/Detection3DArray)
  └ results[].pose.pose.position     → base_link 下的抓取中心点
  └ results[].pose.pose.orientation  → 抓取姿态（tool0 的朝向）
  └ results[].bbox                   → 尺寸，用于判断能否夹住
```

算法流程（桌面固定场景，最稳的路线）：

1. **分割**：HSV 阈值 / `cv2.connectedComponents` 拿彩色方块掩膜（Demo 场景物体颜色固定，比深度学习快且稳）
2. **定位**：
   - 深度相机：取掩膜内点云 → 统计滤波 → 欧式聚类 → 取聚类质心 → 用 RANSAC 拟合桌面平面，质心投影到平面上得到抓取点
   - USB 单目兜底：假设物体放置在 z=桌面高度 的平面上，用内参反投影 + 已知方块尺寸恢复尺度
3. **姿态**：顶抓（top-down），`tool0` 的 +y（两指接近方向）与桌面平行，绕竖直轴对准方块的一条边
4. **逆变换**：`camera_color_optical_frame → base_link` 的 TF 链变换用 `tf2_ros.Buffer.transform()` 完成，**不要手写矩阵**。因为是 eye-in-hand，这条链依赖当前关节角，**必须在采集那一帧的时间戳上查 TF**（`transform(..., msg.header.stamp)`），否则机械臂一动结果就偏
5. **发布**：`Detection3DArray`

**验收**：把方块放在桌面 5 个不同位置，`/detected_objects` 输出的 (x,y,z) 与用尺子量的值误差 < 10 mm；在 RViz 里能看到检测框贴在方块上。

### 阶段 5：抓取规划与任务状态机（2~3 天）

抓取姿态生成（`grasp_planner`）：

```
目标点 P = (x, y, z_table + h/2)
抓取姿态 = 竖直向下，绕 z 旋转 θ 使两指平行于方块边
开口宽度 w = 方块边长 + 2mm 余量，反查阶段 0.5 的映射表得到 hand.angle

pre_grasp  = P + (0, 0, +0.08)      # 接近点
grasp      = P                       # 抓取点
lift       = P + (0, 0, +0.10)      # 提起
place      = 预设放置位姿
```

任务状态机 `pick_place_task`：

```
IDLE → 等待目标
  → OBSERVE          (移动到观察位，采一帧，P 变换到 base_link 后【冻结】)
  → MOVE_PRE_GRASP   (MoveIt 规划到接近点，笛卡尔路径优先)
  → APPROACH         (直线下降到抓取点，不再依赖视觉)
  → CLOSE_GRIPPER    (发 GripperCommand，带 max_effort)
  → LIFT             (直线提起)
  → MOVE_PLACE       (规划到放置点)
  → OPEN_GRIPPER
  → RETREAT
  → IDLE
```

**为什么要有独立的 OBSERVE 步**：相机在手指之间，下降段会进盲区（§3.3）。把观测和抓取解耦，观测一次就冻结目标，抓取段纯粹靠 MoveIt + 冻结的目标位姿 —— 这样盲区问题自然消失，而且失败时容易定位是"看错了"还是"走偏了"。

用纯 Python 状态机即可（`smach` 在 Humble 下维护不活跃），关键是**每一步都要有超时和失败回退**（规划失败 → 重试 3 次并微调姿态 → 仍失败则回 home 并报错）。

**验收**：固定 5 个位置的方块，每个连续抓取 3 次，成功率 ≥ 8/15 起步，逐步优化到 ≥ 12/15。

### 阶段 6：相机到位后的接入（1~2 天）

1. 装 `ros-humble-realsense2-camera`，确认 `/camera/color/image_raw`、`/camera/aligned_depth_to_color/image_raw`、`/camera/color/camera_info`。
2. 深度对齐到彩色（`align_depth.enable:=true`），否则像素与深度对不上。
3. 标定相机内参（`camera_calibration`）——出厂内参通常够用，可跳过。
4. **手眼标定**（见 §5），得到 `tool0 → camera_link`。
5. 把阶段 4 的数据源从 USB 切到 RealSense，代码只改订阅话题名与 `frame_id`。

## 5. 手眼标定（eye-in-hand，已确认）

相机装在机械臂末端，所以要标的是 **`tool0 → camera_link`**（相机相对末端法兰的固定变换）。这个变换一旦标定，结合 TF 就能把任意像素投到 `base_link`。

**为什么 eye-in-hand 比 eye-to-hand 难一点，但值得**：标定结果依赖相机相对末端的刚性安装，**夹爪碰撞、更换夹爪、拧动相机支架都会让标定失效**，必须重标。好处是视野随机械臂走，工作空间不受相机固定视野限制，且能凑近观察。前提是相机支架要做得足够刚，且做好防松标记（画一条记号线，每次开机目视检查）。

流程：

1. 打印 ChArUco 标定板（推荐 ChArUco，部分遮挡下仍能解算），**平放在工作台上固定不动**。
2. 装 `ros-humble-easy-handeye2`，配置 `dummy_arm` 的 group、`gripper_tcp` 为 tracking frame（eye-in-hand 模式下 tracking frame 是**相机**，robot base 是 `base_link`）。
3. 移动机械臂使相机从**多个不同角度、不同高度**看标定板，采 15~20 组。**姿态多样性比数量更重要**：全都从正上方看，旋转分量会解不出来。
4. 求解并检查残差。`easy_handeye2` 会给出 `tool0 → camera_link` 的变换。
5. 写入 xacro 的 `camera_link_joint` 的 `<origin>`，然后 `colcon build` 重新生成。

**精度验证方法**（关键，别只看标定软件自己的残差）：在桌面上放几个标记点，让 `gripper_tcp` 依次走到这些点上方，同时用相机识别同一个点并算出 `base_link` 坐标。**相机算出的坐标与末端实际坐标之差，才是真实的抓取误差** —— 目标 < 5 mm。这个数直接决定抓取成功率，比标定残差有意义得多。

**如果精度不达标**，按这个顺序排查：① 相机支架刚性/安装是否松动 → ② 采集姿态是否过于单一 → ③ 标定板是否在移动 → ④ 关节零位与方向（阶段 0.3）是否有偏差。
