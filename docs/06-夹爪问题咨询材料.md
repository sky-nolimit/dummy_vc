## 一、一句话描述

**这台 Dummy 机械臂的 6 个关节都能正常控制;但只要调用一次夹爪命令
(`hand.set_angle`),夹爪不动,而且此后整个机械臂失去响应,必须断电重启。**

## 二、硬件与固件信息

| 项 | 值 |
|---|---|
| 机械臂 | Dummy(6 旋转关节 + 1 夹爪) |
| 夹爪 | 舵机驱动 + 齿轮齿条 + 两条直线导轨,平行开合,自带驱动板 |
| 夹爪接线 | 从 **j6 的驱动板**引出 |
| 上位机 | Ubuntu 22.04 + ROS 2 Humble,通过 **USB(fibre 协议)** 连主控 |
| 固件源码 | 已获得(作者分享),`dummy-ref-core-fw` |

**从固件源码读到的事实**(`dummy_robot.cpp` / `dummy_robot.h`):

```cpp
DummyHand::SetAngle(float _angle) {          // 角度范围被夹到 0..30
    if (_angle > 30) _angle = 30;
    if (_angle < 0)  _angle = 0;
    uint8_t mode = 0x02;                     // 角度用 mode 0x02
    txHeader.StdId = 7 << 7 | mode;          // CAN 扩展帧,节点 7
    /* 4 字节 float 小端 */
    CanSendMessage(get_can_ctx(hcan), canBuf, &txHeader);
}

DummyHand::SetMaxCurrent(float _val) {       // 电流范围 0..1,默认 0.7
    ...
    uint8_t mode = 0x01;                     // 电流用 mode 0x01
    txHeader.StdId = 7 << 7 | mode;
    CanSendMessage(...);
}

DummyHand::SetEnable(bool _enable) {
    if (_enable) SetMaxCurrent(maxCurrent);  // 注意:使能 = 写电流上限
    else         SetMaxCurrent(0);
}
```

`DummyRobot` 构造函数里:**`hand` 是 CAN 节点 7,与 6 个关节共用同一条 CAN1**
(`motorJ[1..6]` 是节点 1~6)。CAN 波特率约 **1 Mbit/s**(`hcan1.Init.Prescaler = 7`)。

**设备自己也声明了这三个接口** —— 通过 fibre 读到的协议定义里,
`robot.hand` 有 `set_angle`(id 296/297)、`set_enable`(298/299)、
`set_current_limit`(300/301),与固件源码一一对应。

## 三、复现步骤

用上位机直接连 USB(不经过 ROS),每一步都是独立的一次调用。

### 步骤 1 —— 确认基础通信正常

```python
import dummy_cli_tool.ref_tool as ref_tool
robot = ref_tool.find_any(path='usb', timeout=15).robot
robot.set_enable(True)
print(robot.joint_1.angle)          # 读一个关节角
```

**实际结果:1.02 秒返回,读数正常。** 说明 fibre 链路健康。

### 步骤 2 —— 调用夹爪

```python
robot.hand.set_angle(0.0)           # 0 在固件允许的 0..30 范围内
```

**实际结果:永不返回。** 等了 60 秒没有任何应答;手动 Ctrl-C 也无法干净退出,
进程以 libusb 断言失败中止:

```
usbi_mutex_destroy: Assertion `pthread_mutex_destroy(mutex) == 0' failed
Aborted (core dumped)
```

三个方法(`set_angle` / `set_enable` / `set_current_limit`)分别单独测过,
**都是同样结果**。

### 步骤 3 —— 夹爪调用之后再控制关节

```python
robot.hand.set_angle(0.0)           # 永不返回
robot.move_j(0, 0, 90, 0, 0, 0)     # 然后再发一条关节命令
```

**实际结果:**

| 顺序 | 结果 |
|---|---|
| 夹爪调用**之前** `move_j(-15,0,90,0,0,0)` | **j1 正常转 15 度** ✅ |
| 夹爪调用**之后** `move_j(...)` | **永不返回,终端无任何输出** |

**也就是说:一次夹爪调用之后,整台机械臂就不响应了,直到断电重启。**

## 四、我们据此做的推断(**这部分是推断,不是实测**)

固件里所有 CAN 发送都走同一个函数:

```cpp
// Bsp/communication/interface_can.cpp
void CanSendMessage(CAN_context* canCtx, uint8_t* txData, CAN_TxHeaderTypeDef* txHeader)
{
    if (canCtx->handle->Instance == CAN1)
        semaphore_status = osSemaphoreAcquire(sem_can1_tx, osWaitForever);  // ★ 永久等待
    else if (canCtx->handle->Instance == CAN2)
        semaphore_status = osSemaphoreAcquire(sem_can2_tx, osWaitForever);
    else
        return;

    if (semaphore_status == osOK)
        HAL_CAN_AddTxMessage(canCtx->handle, txHeader, txData, &canCtx->last_heartbeat_mailbox);
    // ★ 函数自己不释放信号量
}
```

**两个要点:**
1. 取信号量是 `osWaitForever`(**永久等待**)
2. **函数自己不释放信号量** —— 释放应由 CAN 发送完成回调负责

**电机和夹爪共用这一个函数、同一条 CAN1。** 所以如果 TX 完成回调对夹爪那一帧
不触发,信号量就再也回不来,固件永久卡在 `osSemaphoreAcquire` 里 ——
**此后所有 CAN 发送(包括电机)都阻塞。**

**这与观察到的现象完全吻合:** 夹爪不动(帧没发出去)、调用不返回(固件卡住)、
之后电机也不响应(同一个信号量)。

**"回调为什么不触发"我们无法从软件判断**,可能的原因:

1. **CAN 总线在发夹爪那一帧时进入 error-passive 或 bus-off** ——
   缺终端电阻、H/L 接反、断线、或舵机波特率与 1 Mbit/s 不符
2. 固件在夹爪这条路径上有 bug

## 五、我们想知道的

**请按重要性回答,能答几条是几条:**

1. **这台设备的夹爪,出厂时有没有被验证过能通过机器人软件控制?**
   (即:有没有用过 `robot.hand.set_angle` 这样的调用,并且成功让它动?)

2. **夹爪的舵机具体是什么型号?** 是不是标准的总线舵机?
   - CAN 节点 ID 是不是 **7**?
   - 波特率是不是 **1 Mbit/s**?
   - 有没有单独的说明书或规格书?

3. **夹爪那条 CAN 总线上有没有终端电阻?** 在哪里?
   总线两端分别是什么设备?

4. **有没有夹爪的接线图或引脚定义?** 特别是从 j6 驱动板引出的那几根线。

5. **CAN_H / CAN_L 能不能从外部引出来?** 我们想用一个 USB-CAN 适配器
   直接挂在总线上,自己扫节点、确认舵机到底在不在线。
   **如果有现成的接线点,请告诉我们位置。**

6. **`set_enable` 的语义确认:** 从源码看它只是"把电流上限写成
   `DummyHand::maxCurrent`(默认 0.7)",并不是一条独立的使能指令。
   这是设计如此,还是固件不完整?

7. **有没有已知的夹爪使用注意事项?** 比如必须先设某个模式、某个参数,
   或者对时序有要求。

## 六、我们观察到的其他事实(**供参考,不是问题**)

- **舵机是通电的**:执行 `robot.set_enable(True)` 之后,用手拨两个手指会感到
  明显阻力(有力矩);不执行时手指可以轻松拨动。**所以舵机供电正常。**
- **夹爪自然断电姿态是完全闭合的**(据观察)。
- **夹爪的线没有断、插头没有空位**(目视确认过)。
- 参考项目 `dummy_moveit_ws` 里**夹爪相关代码全部被注释掉了**
  (`MOVE_GROUP_GRIPPER`、`gripper_joint_names`)。**原作者似乎也没能解决这个。**
  这一点如果属实,是否说明这个夹爪在你们那边也一直没能调通?
